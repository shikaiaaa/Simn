# RQ-0001 Sinn · 虚拟形象与虚拟试穿

> 本文件是**原始需求**，不是规格。SA 负责把它变成可验收的需求文档 `docs/sa/REQ-0001.md`。
> 第四节是 Lead 的技术现实备注，**不属于用户需求**，用于和用户对齐边界。

## 一、用户原话（2026-11-09）

> 用户可以上传自己的身体数据，包括但不限于照片、身高、体重、三维等数据，然后小程序根据用户外貌体型生成一个用户虚拟人物形象，越贴近用户真实外貌越好，用户可以根据上传衣服照片，来模拟自己穿上衣服的样子，看是否合身，模拟完成后，小程序支持放大查看穿着细节等能力。

## 二、拆成四条能力

| 编号 | 能力 | 用户的原话依据 |
|---|---|---|
| R1 | 身体数据采集：照片 + 身高 / 体重 / 三围，可能还有肩宽、臂长、腿长 | "上传自己的身体数据，包括但不限于照片、身高、体重、三维" |
| R2 | 生成虚拟人物形象，"越贴近真实外貌越好" | "根据用户外貌体型生成一个用户虚拟人物形象" |
| R3 | 虚拟试穿：上传衣服照片，看自己穿上的样子 | "根据上传衣服照片，来模拟自己穿上衣服的样子" |
| R4 | 放大查看穿着细节 | "支持放大查看穿着细节等能力" |

`看是否合身` 贯穿 R3/R4，但它到底是"看起来合身"还是"尺码合身"，必须问清（见第三节 3）。

## 三、SA 必须问清的问题（不回答就无法拆任务）

1. **"贴近真实"的验收标准**：是"脸像本人"，还是"体型比例对"？两者技术路径完全不同，一个偏人脸重建，一个偏人体参数化。
2. **虚拟形象是什么形态**：一张 2D 图？可旋转的 3D 模型？一段短视频？这三种成本差一个数量级。
3. **"合身"的判据**：视觉上看着合身（生成图近似），还是要给出尺码结论（S/M/L、松紧判断、哪个部位紧）？后者必须有衣服的真实版型数据。
4. **衣服照片从哪来**：用户拍自家衣服、拍吊牌尺码、还是商家商品图？三种输入的算法难度差很多。
5. **支持哪些品类**：上衣 / 裤子 / 裙子 / 外套 / 鞋 / 配饰？是否要多件叠穿、上下装组合？
6. **数据留存**：只做单次生成，还是要保存多个形象、历史记录、分享给朋友？
7. **隐私底线**：人体照片属敏感个人信息，用户是否接受"上传即处理、处理完即删、不留存"？是否要支持随时删除？
8. **商业化**：免费额度多少、付费点在哪（生成次数 / 高清图 / 3D 形象）、是否需要商家端（服装店上传自己的商品）。

## 四、Lead 备注：技术现实（非需求，需与用户对齐后再写进 SPEC）

1. **小程序端不做推理。** 人体重建、试穿生成都必须在服务端 GPU 完成；小程序只负责采集、上传、轮询、展示。端上只适合轻量 3D 展示（WebGL / glTF），且本项目是 skyline 渲染器，WebGL 可用性要先验证再承诺。
2. **2D 试穿是当前唯一能工程化落地的路径。** 上传 1–3 张人像 + 1 张衣服图，服务端扩散模型换装，单张数秒到十几秒。市面上有商用 API（例如 [Perfect Corp 的模块化试穿 API](https://www.perfectcorp.com/fr/business/news/perfect-corp-devoile-de-nouvelles-api-mode-en-ia-generative)），也可以自建（OOTDiffusion / IDM-VTON / CatVTON 一类开源模型）。
3. **3D 数字人可做，但"贴近真实"很贵。** 参数化体型（SMPL-X 一类）能给出比例，但用照片反推三围是厘米级误差，不能当量体用；高保真定制数字人属企业级预算（参考 [Humanetics 的 3D avatar 方案](https://www.humaneticsgroup.com/sites/default/files/2026-02/Flyer_SizeNA_Avatars_e.pdf)）。
4. **"是否合身"是三条里最难的一条。** 视觉合身可由生成图近似；尺码合身需要"服装真实版型数据 + 人体围度"，本质是规则引擎 + 版型库，不是模型问题。没有商家提供版型时，只能给"参考尺码"，不能承诺合身。
5. **合规硬约束**：人体照片是敏感个人信息，需单独同意、最小化收集、可删除；AI 生成内容需按《人工智能生成合成内容标识办法》做标识；若涉及导购/电商，还要看类目资质。

**建议分期（需用户确认，确认前 SA 不得按"全都要"写需求）：**

- **P1 可交付**：照片 + 身高体重三围 → 2D 试穿效果图 + 参考尺码 + 双指放大细节。
- **P2**：多角度、轻量 3D 形象（glTF），可旋转查看。
- **P3**：真正的合身判断，依赖服装版型库与商家合作。

## 五、验收草案（供 SA 细化，不是最终 AC）

- 上传 1–3 张照片 + 数值，端到端 60 秒内出图（超时要给进度与失败原因）。
- 出图可双指放大到看清纹理，放大后不糊、不出现明显拼接痕迹。
- 照片不合格（非全身、遮挡、多人、逆光）有明确提示，且**不能静默生成一张错的图**。
- 用户可一键删除自己上传的照片与生成结果，删除后服务端确实不再持有。
- 生成图带 AI 生成标识。
