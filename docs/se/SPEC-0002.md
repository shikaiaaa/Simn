## 方案概述

P2 在 P1（2D 虚拟试穿，内部 demo）基础上新增「轻量 3D 人像形象」与「P1.1 单件下装/裙装/外套（2D）」两条能力。端上仍只负责采集、压缩、上传、轮询、渲染与展示，**端上零推理**；3D 生成由服务端异步调用第三方 3D 生成 API，返回可旋转的 glTF/GLB + 纹理；渲染方案已由 SPIKE-0002 在开发者工具实测纠正并写死：xr-frame **组件模式**渲染 + **3D 查看页页面级 `renderer:"webview"`**（其余页面保持 skyline）；three.js 仅作备选记录。真机矩阵（帧率/内存/手势/同层 HUD）仍未验证，见 CP-02-06。历史形象库在 demo 期不设数量与保留期上限；删除/撤回同意一律物理全删；AI 标识在查看页固定展示、保存相册的静帧内烧入水印；P1.1 2D 品类复用 P1 的采集、生成与尺码链路，仅扩展衣服品类与不合格判定。

### 1. 端到端链路（3D）

0. **启动前置门禁**：沿用 P1 低版本检测（`typeof wx.getSkylineInfo === 'function'` + `try/catch`）；3D 入口此外检查渲染能力（`inspectRenderCapability()`：基础库版本、`wx.createSelectorQuery` 可用性、WebGL/GLTF 加载器可用性，具体判定由 SPIKE-0002 结论确定）；不满足时隐藏 3D 入口并提示升级/切 2D，不初始化 3D 业务。
1. **进入 3D 生成**：首页「3D 形象」入口 → `package-3d/pages/model3d-create/index`；首次使用者须已有 P1 的有效同意记录（含 3D 披露节，§F），否则先走 P1 `pages/consent/consent`。
2. **采集**：复用 P1 采集能力（相册/相机 + 人像 1–3 张 + 身高体重必填 + 性别/三围选填；3D 输入质量要求更高：单人、全身或膝上、正脸清晰、光线均匀、无遮挡、长边足够）；端上 L0 粗筛（格式/大小/长边，≤300ms 同步拦截，不发网络）。
3. **端上压缩**：复用 P1 `compressToVendorSpec`（尺寸档 × 质量档、先降质量再降尺寸、达标即停、全用尽失败），最终提交规格 = 长边 ≤4096px 且 ≤5MB 且 JPG；因供应商限制压缩时提示「已自动优化照片（供应商限制）」。压缩失败返回 `5007`，不建任务、不上传原图。
4. **上传与登记**：压缩后 JPEG 上传云存储 → `assetRegister` 绑定 openid；不缓存原图与中间产物。
5. **服务端预检**：`sinn-model3d` 的 `precheck`（复用 P1 预检 + 3D 输入附加判定）；服务端二次校验为准，端上预检只拦截不承诺放行。
6. **创建任务**：`model3dSubmit`，服务端校验同意记录、输入规格（≤4096px/≤5MB/JPG/1–3 张）、并发限制与可配日上限；通过后创建 `sinn_tasks`（taskType=`3D_MODEL`，status `QUEUED`），记录 `clientReqId`、`startedAt`、`purgeAt`（失败留存用）；**不扣 2D 额度**。
7. **提交供应商**：`Model3dVendorAdapter.submit` → `vendorJobId`，状态 `GENERATING`；供应商无独立预检端点时按 §B.4 失败码映射兜底。
8. **端上轮询**：2s 起，2s→4s→8s 退避（上限 8s），总等待硬上限 310s；服务端 `query` 供应商 → 成功则 `fetchAsset` 下载 → 校验格式/大小 → 转存云存储 → 写入 `sinn_models3d` → 状态 `SUCCEEDED`；>300s 服务端判 `TIMEOUT`（`5002`）。
9. **渲染与后续**：端上按 D-1 加载模型：3D 查看页（页面级 `renderer:"webview"`）内以 xr-frame **组件模式**加载 GLB + 纹理（加载进度、单模型 60s 超时、失败重试 ≤2 次、命中本地缓存直接展示）；查看页支持水平 360°、俯仰 ±30°、双指缩放 0.8–2x、自动旋转开关；成功后自动入历史库；保存相册输出当前视角静帧 JPG（烧入「AI 生成」水印）；删除本次/删除全部/撤回同意走物理全删。
10. **失败与留存**：失败/超时任务的原照片与中间产物标记 24h 可重试；24h 后 `sinn-cleanup` 物理删除对象与记录；成功模型与纹理在 demo 期长期保留，直到用户删除或撤回同意。

### 2. 状态机、进度与失败

- 服务端状态（复用 P1 状态机，`taskType=3D_MODEL`）：`QUEUED` → `GENERATING` → `SAVING` → 终态 `SUCCEEDED` / `FAILED` / `TIMEOUT` / `CANCELLED`；**无 `PURGED` 状态**（删除即物理删除记录，见 §4）。
- 供应商阶段映射（SPIKE-0002 候选 A 实测：Tripo task_status PENDING/RUNNING/SUCCEEDED/FAILED/CANCELED/UNKNOWN）：`SUBMITTED`→`QUEUED`，`PENDING/BUILDING`→`GENERATING`，`TEXTURING/FINALIZING`→`GENERATING`（stage 记 `TEXTURING`），`SUCCEEDED`→`SAVING`→`SUCCEEDED`，`FAILED`→`FAILED`。
- 客户端展示阶段：`UPLOADING` / `PRECHECKING` / `QUEUED` / `GENERATING`（含 stage 子阶段 `MODELING`/`TEXTURING`/`SAVING`）/ `DONE` / `FAILED` / `TIMEOUT` / `CANCELLED`；显示已等待秒数与预计剩余（ETA 由服务端基于 stage 与历史 P50 估算，**不造假百分比**）。
- 等待态提示：<60s 显示「正在生成 3D 形象」；≥60s 起可显示「生成较慢，请稍候」；≥180s 提示「3D 生成耗时较长，可离开页面稍后回来查看」但仍继续轮询；>310s 端上进入超时态（服务端异常兜底），显示「生成超时，请重试」。
- 失败分类（复用 P1 失败分类 + 3D 专项）：照片不合格 / 内容安全 / 网络失败 / 供应商不可用或排队超时 / 生成失败 / 生成超时 / 模型损坏或解析失败；每类不同文案 + 下一步动作；禁止静默失败、禁止占位模型、禁止用旧模型冒充新结果；失败页不得展示任何结果模型。
- 成功判定：模型文件可访问且加载器解析成功（节点数/网格数 >0）；解析失败归 `FAILED`（`6002`），可重试。

### 3. 长任务、幂等与恢复

- 服务端超时：默认 `300000ms`（`SINN_MODEL3D_TIMEOUT_MS` 覆写，0/负数/非数字回退默认）；**仅 >300s** 才置 `TIMEOUT` + `failure.code=5002`，并由 cleanup/对账逻辑标记失败；**不扣费、不涉及 2D 额度返还**。
- 端上：轮询 2s 起，2s→4s→8s 退避；总预算 300s + 10s 缓冲 = **310s 硬上限**；收到服务端 `TIMEOUT` 立即进超时态；离开页面不取消任务，返回按 `taskId` 续查同一任务。
- 恢复：提交成功写本地 `sinn_active_model3d_task_v1`（仅 taskId/createdAt/stageHint），再次进入 3D 生成/查看页时优先查询该 taskId；终态、删除、撤回同意时清除。
- 幂等：`(openid, clientReqId)` 唯一；重复提交同一 `clientReqId` 返回同一 `taskId`，不重复建任务、不重复提交供应商；端上「开始生成」点击后在请求返回前禁用按钮。
- 并发：同一用户同时最多 1 个进行中 3D 任务；第 2 个提交返回 `2002 E_ACTIVE_TASK_EXISTS` 并带 `existingTaskId`；P1 的 2D 任务与 3D 任务互相独立（各自 `activeTaskId` / `activeModel3dTaskId`）。
- 日上限（成本保护，RK-13）：`SINN_MODEL3D_DAILY_LIMIT` 默认 `0` = 不限；配置 N 时第 N+1 次提交返回 `6006 E_MODEL3D_DAILY_LIMIT`（429），提示「今日 3D 生成次数已用完」，**不得伪装成生成失败**；demo 默认不限。
- 重试：失败/超时任务可在 24h 内用同一批已上传照片重新提交（新 `clientReqId`、新 `taskId`）；原照片 24h 后物理删除，不可重试。

### 4. 删除、历史库与留存

- **历史形象库（demo）**：不设数量与保留期上限；3D 生成成功后自动入库（`sinn_models3d.status='READY'`）；列表按 `createdAt` 倒序，含缩略图/时间/状态；点击切换查看；支持单删与删除全部；账号同步（同一 openid 换设备可见）。
- **删除本次**：物理删除该模型记录、`sinn_tasks` 记录、云存储 `model.glb`/纹理/缩略图与本地缓存；响应返回 `deletedAt`（**不落库**）；再次查询 `404`（`E_TASK_NOT_FOUND` / `E_MODEL3D_NOT_FOUND`）；无 tombstone、无 `PURGED` 状态。

- **留存边界解释**（与 RK-15 相关）：BR-15 的「24h 清理」只适用于失败/超时任务与中间产物；成功模型属历史库资产，长期保留。该解释写入本 SPEC，若用户评审认为应改为「成功任务的原照片也 24h 删除」则按 REQ 变更处理（R-02-14）。

### B.4 Model3dVendorAdapter 契约抽象

#### B.4.1 契约方法（必需 4 + 可选 2）

| 方法 | 入参 | 出参 | 语义 |
|---|---|---|---|
| `submit` | `{ openid, personFileIDs[], metrics, options? }` | `{ vendorJobId, provider, submittedAt }` | 异步提交，返回供应商任务 ID（如 Tripo `task_id`；异步头 `X-DashScope-Async: enable` 形态）；8s 内返回任务 ID，不得同步长阻塞 |
| `query` | `{ vendorJobId }` | `{ status: 'PENDING'\|'BUILDING'\|'TEXTURING'\|'SUCCEEDED'\|'FAILED'\|'CANCELLED', stage?, etaSec?, failureCode?, failureMessage?, assetUrl? }` | 轮询状态；供应商状态映射见 §B.4.1 说明；成功时返回可下载的短效资产 URL（不落盘） |
| `fetchAsset` | `{ vendorJobId }` | `{ format:'glb'\|'gltf'\|'zip', bytes, url? , stream? }` | 下载结果资产；只接受白名单格式（优先 GLB），校验大小上限（≤45MB）；**处理 URL 过期**（如 Tripo 结果 URL 2h 有效）：过期/403/404 时重新 `query` 取新 URL 再下载；不得把过期 URL 下发客户端长期保存 |
| `health` | `{}` | `{ ok:boolean, provider, checkedAt }` | 健康检查；未配置凭证时 `ok:false`（不抛异常） |
| `cancel`（可选） | `{ vendorJobId }` | `{ unsupported?:true } \| { ok:true }` | 供应商不支持取消时允许返回 `{unsupported:true}`，服务端置 `CANCELLED` 并停止轮询 |
| `erase`（可选） | `{ vendorJobId }` | `{ unsupported?:true } \| { ok:true }` | 供应商不支持删除时返回 `{unsupported:true}`，服务端以我方删除 + 供应商侧留存按合同披露兜底 |

- `vendorJobId` 语义：供应商返回的任务 ID（如 Tripo `task_id`，24h 内可查）；服务端持久化 `vendorJobId` 供续查，不把供应商任务 ID 暴露给客户端（客户端只认 `taskId`）。
- 状态映射：候选 A（Tripo）`PENDING/RUNNING/SUCCEEDED/FAILED/CANCELED/UNKNOWN` → 内部 `PENDING/BUILDING/SUCCEEDED/FAILED/CANCELLED`；`UNKNOWN` 不得当成功，保持 `GENERATING` 至 300s 超时或按 `6002` 失败。
- 结果 URL 有效期：候选 A 结果 URL 2h 有效、任务 `task_id` 24h 有效；`fetchAsset` 必须「先 query 取最新 URL → 再下载」，URL 过期/403/404 时重查重试（上限 2 次），仍失败返回 `6001`/`6002`，不得缓存过期 URL。
- 提交形态：候选 A 为「提交任务→轮询→结果 URL→下载转存」，候选 B/C 为「提交任务→轮询→结果文件列表/下载」；适配器层统一为 §B.4.1 契约，候选差异只体现在实现内部。
- `E_MODEL3D_UNAVAILABLE`(6001)：供应商不可用/网络/鉴权/限流/余额类；**业务参数错误不得兜底为 6001**。
- `unknown` 语义：若候选供应商返回无法识别的状态，`query` 返回 `status` 缺失 → 服务端按 `E_MODEL3D_PARSE_FAILED`(6002) 或保持 GENERATING 到 300s 超时；不得当作成功。

- 环境变量：`SINN_VENDOR_3D=mock|tripo|tencenthunyuan|volcark|meshy|rpm`（默认 `mock`）；`SINN_3D_AK`/`SINN_3D_SK`/`SINN_3D_REGION`；`SINN_MODEL3D_TIMEOUT_MS`（默认 300000）；`SINN_MODEL3D_DAILY_LIMIT`（默认 0）。

## 边界与错误处理

| 场景 | 期望行为 |
|---|---|
| 3D 入口、设备/版本不支持 | 首页入口隐藏或置灰 + 提示升级/使用 2D；不进入 3D 页、不初始化渲染、不白屏（AC-14） |
| 未同意 3D 披露节就进入生成 | 跳回同意页；不调用相册/相机、不上传（AC-19/21） |
| 照片 0 张 / >3 张 | 端上拦截并提示「请上传 1–3 张全身照」；不建任务（AC-2） |
| 非全身/多人/遮挡/逆光/分辨率过低 | 预检拒绝 + 明确文案；createTask 0 次（AC-3） |
| 照片超供应商规格（>5MB/>4096px/非 JPG） | 端上 `compressToVendorSpec` 处理；压后仍超 → `5007`，不 uploadFile、不建任务（AC-4） |
| EXIF 竖拍 | 压缩后方向保持竖向（AC-4） |
| 小图（如 2048px/2MB） | 不压缩、不提示，字节与长边保持（AC-4） |
| 重复提交同一 `clientReqId` | 返回同一 taskId，不重复创建/提交（AC-22） |
| 已有进行中 3D 任务时再次提交 | `2002 E_ACTIVE_TASK_EXISTS` + `existingTaskId`，提示已有任务，可跳转查看（AC-13/22） |
| 日上限耗尽（配置 N>0） | `6006 E_MODEL3D_DAILY_LIMIT`(429)，提示今日次数已用完；不伪装生成失败（AC-27） |
| 离开生成页再返回 | 按 `taskId` 续查同一任务，轮询继续，不重复建任务/不重复扣费（AC-22/30） |
| 供应商不可用/鉴权/限流 | `6001 E_MODEL3D_UNAVAILABLE`(503)，文案「服务暂不可用，请稍后重试」，可重试（AC-3/30） |
| 供应商排队/生成超时（>300s） | 服务端 `TIMEOUT` + `5002`；端上进超时态，文案「生成超时，请重试」；不展示占位模型（AC-1/30） |
| 端上 310s 硬上限（服务端异常） | 端上进超时态并提示；重新进入可查询服务端真实状态（AC-1） |
| 模型损坏/解析失败 | `6002 E_MODEL3D_PARSE_FAILED`，提示重试/删除，不白屏；历史库该条标失败可删（AC-23） |
| 模型超 45MB/纹理超限 | 服务端拒绝入库并 `6003 E_MODEL3D_TOO_LARGE`；任务置失败，可重试（AC-5） |
| 生成中删除本次任务 | `6005 E_MODEL3D_GENERATING`(409)，提示「生成完成后可删除」或先取消（AC-22） |
| 删除本次（成功模型） | 物理全删对象 + 记录 + 本地缓存；响应 `deletedAt`；再查 404（AC-9/29） |
| 重复删除 | `5004 E_TASK_NOT_FOUND`(404)；删除全部幂等成功（AC-9/29） |
| 删除全部/撤回同意 | 物理全删全部 3D 资产与记录、清缓存；响应 `deletedAt`；查询为空（AC-29） |
| 24h 后清理失败/超时任务 | 对象 HEAD 404、记录不存在；成功模型不受影响（AC-28） |
| 历史库为空 | 空态提示「还没有 3D 形象，去生成一个」；不报错（AC-7） |
| 列表分页越界/非法 limit | `1001 E_PARAM`；不返回脏数据（AC-7） |
| 模型缓存超限 | 按 LRU 淘汰最久未访问，保持 ≤5 个/≤200MB；不崩溃（AC-24） |
| 缓存文件损坏 | 删除并重新下载；不展示损坏模型（AC-23） |
| 相册保存被拒绝 | 提示「无法保存到相册，可在页面查看」；不阻断查看（AC-10） |
| 保存相册成功 | 生成带「AI 生成」水印的 JPG 且文件存在；无 glTF/视频导出入口（AC-10/12） |
| 全部候选结构保真不达标 | 按 RK-14 回报用户，不得私自降口径、不得用重绘五官方案冒充（AC-25） |
| 网络失败/弱网 | 明确失败文案 + 重试；不静默失败（BR-4） |
| 未授权查看他人模型 | 按 404 返回，不泄露存在性（AC-26） |
| 日志与埋点 | 不含照片、人脸、3D 资产 URL、openid 明文；只记录 taskId/modelId/code/耗时（BR-12/§6.5） |

## 非功能要求

- **性能**：3D 端到端 ≤300s（AC-1）；服务端超时默认 300s（env 覆写）；端上轮询 2s→4s→8s、硬上限 310s；计时边界 = createTask 成功返回 → 模型可访问且加载器解析；记录真实 P50/P95，不得把 300s 写成常态；模型下载（≤45MB，SPIKE 实测候选 A 输出 42.3MB/44.5MB）首帧可交互目标 ≤5s（Wi-Fi 环境，真机实测，AC-24）；加载显示进度、单模型 60s 超时、失败重试 ≤2 次；旋转帧率 ≥30fps（低端机 ≥24fps 并记录）；连续旋转 60s 不崩溃（AC-6/24）。
- **兼容**：skyline + glass-easel 基线不变；3D 查看页 `renderer: "webview"` 与其余 skyline 页共存；旧版 8.0.30/3.0.0 兜底；iPad 750rpx 居中；深色模式不启用；安全区沿用；`lazyCodeLoading: requiredComponents` 保持。
- **权限**：仅相册/摄像头/隐私授权/相册写入（§F 已登记）；未同意不调用；3D 入口在能力不足时不初始化渲染；禁止 eval/new Function/动态 require/import 拼接路径。
- **安全**：模型只允许来自白名单供应商/我方云存储；入库前校验格式（glb/gltf magic）、大小、节点数；下载 URL 短期签名（≤10 分钟）；云存储按用户隔离，demo 安全规则已知限制沿用 P1 R-12；缓存不含原资产 URL/openid；日志脱敏。
- **可观测性**：结构化日志 `requestId/action/taskId/modelId/vendorProvider/code/latencyMs`；服务端保存 `startedAt/finishedAt`、stage 切换时间、失败码；P50/P95 供 AC-30 证据。
- **可用性**：demo 不承诺 SLA；供应商不可用时明确失败（6001）并可重试；不静默失败、不占位模型、不缓存旧模型冒充新结果。
- **成本**：demo 3D 不限额（Q-6），仅通过并发 1 + 可配日上限（默认 0）+ 真实调用总预算（CP-02-07）控制；成本敞口记录 R-02-03/RK-13。
- **合规**：BR-1..BR-15 落到 F-02-01..F-02-15；demo 与上线版差异引用 REQ §3.3（13 项）；上线前必须补 3D 单独同意与隐私评估。
