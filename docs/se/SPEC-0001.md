## 方案概述

整体思路：小程序端只做采集、上传、轮询、展示（决策 C1，端上零推理）；服务端用**微信云开发**承载身份、额度、任务、文件与清理；2D 换装由**第三方商用试穿 API**异步生成，服务端做供应商契约抽象，未采购前用**契约桩（mock provider）**驱动开发与测试，DEV 不因采购阻塞；结果图以单图源 1x–3x 双指缩放展示，配「AI 生成」显式标识与参考尺码区间；照片与结果按 ≤24h 或用户删除（取先）自动清理。

### 1. 端到端链路

1. **启动**：首页展示功能说明与「开始」；若本地/服务端已有进行中任务，展示「继续上次生成」入口（AC-12）。
2. **合规门禁**：未同意 → 进入 `consent` 页，两步显式确认（18+ 声明 → 隐私单独同意，含境内第三方受托处理方披露）；拒绝则停留功能说明、**不调用任何隐私接口**（AC-21/25）。
3. **采集**：`capture` 页人像 1–3 张 + 身高/体重 + 性别（选填，默认 `unspecified`，可跳过）、三围（选填），每项可单独重拍/修改；端上 L0 启发式拦截 → 上传云存储 → 服务端 `precheck` 二次校验（L1 视觉模型/规则，方案待选型；供应商无独立预检端点；`validate` 三态 `pass|fail|unknown`，**`unknown` 不放行**；目标 ≤5s，硬超时 8s）→ 不合格/无法判定给具体原因与重拍建议，**不创建任务**（AC-2/3/4/5）。
4. **衣服**：`garment` 页单张上装照片，同样走 L0 + 服务端二次校验（同上，`unknown` 不放行）；四类不合格（吊牌/多件/模特上身/电商图）拦截，**不创建任务**（AC-24）。
5. **创建任务**：`createTask` 原子校验额度 + 单活跃任务 + 幂等键（`clientReqId`），预扣额度，提交供应商，返回 `taskId`（AC-11/12）。
6. **生成中**：`generating` 页每 2s 轮询 `taskGet`，展示真实阶段 + 已等待秒数；服务端在供应商成功时下载结果、转存云存储；60s 未成功判 `TIMEOUT` 并返还额度（AC-7/8/9）。
7. **结果**：`result` 页展示结果图（单图源 1x–3x 缩放、平移、复位）+ 「AI 生成」显式标识 + 参考尺码区间/对应标准名（GB/T 1335.1 / 1335.2 / 中性映射）/免责/三围缺失降级；支持「删除本次数据」（AC-13..19、AC-26）。
8. **我的**：`profile` 页展示剩余次数/重置时间/VIP 标识、删除全部、撤回同意（AC-11/19/21）。
9. **清理**：`sinn-cleanup` 定时任务清理 24h 前**未删除**的任务及其云存储对象（物理删除，不留状态）；删除与清理后查询一律按不存在处理（`E_TASK_NOT_FOUND` 404，BR-8/BR-9）。

### 2. 任务状态机与客户端展示阶段

- 服务端状态：`QUEUED → GENERATING → SAVING → SUCCEEDED`；任意进行中状态可转 `FAILED` / `TIMEOUT` / `CANCELLED`。终态：`SUCCEEDED` / `FAILED` / `TIMEOUT` / `CANCELLED`。
- **无 `PURGED` 状态**（CP-08）：用户删除即物理删除任务记录与云存储对象，记录不进入任何中间/墓碑状态；24h 到期清理同样直接物理删除，不保留状态。
- 客户端展示阶段（由服务端 `stage` 字段下发，端上不推算）：`UPLOADING` / `PRECHECKING` / `QUEUED` / `GENERATING` / `SAVING` / `DONE` / `FAILED` / `TIMEOUT` / `CANCELLED`。
- **不造假百分比进度**：只显示阶段名与已等待秒数（AC-8）。
- 同一用户同时最多 1 个进行中任务；重复创建返回 `E_ACTIVE_TASK_EXISTS` + `existingTaskId`，端上直接恢复该任务（不重复扣额度）。

### 3. 额度与幂等

- 普通用户 1 次/日、VIP 10 次/日，Asia/Shanghai 每日 00:00 重置；`dayKey` = `YYYY-MM-DD`，读取时惰性重置（`dayKey` 不同则 `usedToday=0`）。
- 实现口径：`createTask` **预扣**（原子条件更新），成功保留；失败/超时/内容安全拦截/用户取消按 `taskId` **幂等返还一次**（`quotaRefunded` 标记），对外表现为「仅成功扣额度」（BR-5/Q-13）。
- 幂等键：`(openid, clientReqId)`；客户端生成 UUID v4，重复提交返回同一 `taskId`，不重复扣减（AC-12）。
- VIP 识别：demo 用 `sinn_config.vipWhitelist`（openid 列表）或后台配置开关，不做支付/会员体系（Q-20，CP-09）。

### 4. 删除、留存与 AC-20 口径

- **删除本次**（结果页）：二次确认后，物理删除本次任务记录（含身高/体重/三围/性别等尺寸与任务元数据）、关联资产记录（人像/衣服）与云存储对象（人像/衣服/结果）；在删除接口成功返回前完成物理删除，响应返回 `deletedAt`（服务端时间，**不落库**）；用户侧立即不可见；成功额度不返还。失败任务的原图与记录同样物理全删。
- **删除全部**（我的）：物理删除该用户全部任务记录、资产记录与云存储对象，取消进行中任务并返还其额度（BR-5）；保留 `sinn_consents` 同意审计（用户/版本/时间/撤回记录，不含照片、身高体重三围与性别）与 `sinn_users` 的额度/同意状态（不含照片与围度）；响应返回 `deletedAt`（不落库）。删除全部不重置当日已用额度（成功额度不返还）。
- **撤回同意**（我的）：等同删除全部 + 服务端同意状态置撤回 + 清本地缓存，之后重新走同意流程（BR-11）。
- **删除幂等**：`deleteTask` 对已不存在的 taskId 返回 `E_TASK_NOT_FOUND`（404，按不存在处理）；`deleteAll` 幂等（无数据可删也返回成功，`deletedAt` 为本次服务端时间）。
- **24h 留存**：`purgeAt` = 任务创建时间 + 23h（预留 1h 余量，保证物理删除 <24h）；`sinn-cleanup` 每 10 分钟执行，**仅清理未删除且已到 `purgeAt`** 的任务及其对象与记录，不留 purge 状态；已被用户删除的任务不进入 24h 等待。
- **AC-20 断言口径**：云函数通过 `callFunction` 返回，不存在 HTTP 状态码；本 SPEC 约定 AC-20 的「404/410」以**响应体 `error.httpStatus` + `error.code`** 表达。因删除与清理均为物理删除，不存在「记录在但已删除/已过期」的中间状态，**所有查询与删除统一返回 404 `E_TASK_NOT_FOUND`**；`E_TASK_GONE`（410）为保留位、P1 不使用（见错误码表）。删除成功响应含 `deletedAt`；对象存储「HEAD 404」以服务端 `getTempFileURL` 返回非 0 status 或对象不存在表达；数据库「记录不存在」通过测试环境 `auditTask` 断言 `exists=false`（无 purged 墓碑、无删除时间戳记录，见 B.2 API-11）。该差异不影响 AC-20 意图，记录在 R-6。
- 越权访问他人任务统一按 `404` 处理（不泄露存在性），内部日志告警。

### 5. 参考尺码（服务端计算，端上零推理）

- 输入：`metrics.gender`（`male` / `female` / `unspecified`，选填，默认 `unspecified`，可跳过不阻塞生成）+ 身高/体重必填 + 三围选填（BR-1，CP-06）。
- 输出结构：`{rangeMin, rangeMax, standard: "GB/T 1335.1" | "GB/T 1335.2" | "GB/T 1335（中性映射）", basis: {heightCm, weightKg, chestCm?, waistCm?, hipCm?}, disclaimer: "参考尺码，不构成合身承诺"}`；区间必须落在 `XS/S/M/L/XL/XXL` 六档内，相邻两档为区间（AC-16）。
- 映射规则（BR-4，CP-06）：`male` → **GB/T 1335.1 男装表**；`female` → **GB/T 1335.2 女装表**；`unspecified`（默认）→ **中性六档简化映射**（以身高为主档，体重/BMI 至多调整 ±1 档，边界收敛到 `XS`/`XXL`）。若用户填了三围，用填写数值收窄区间；**不得从照片反推围度**。
- 展示：结果页显示「参考尺码：M–L（GB/T 1335.1）」等**对应标准名** + 依据（身高/体重/三围）+ 固定免责「参考尺码，不构成合身承诺」。三种 gender 取值都必须能显示区间；**性别不填不影响出区间**（AC-16/AC-26）。
- **三围全缺**：`sizeResult=null` + 固定文案「信息不足，无法给出参考尺码」，不编造区间（AC-17，Q-5）。
- 文案红线：不得出现「保证合身 / 精准 / 准确 / 适合你」等结论性表述（AC-16/AC-26 正则断言）。

### 6. 合规基线（P1 demo 仍必须满足）

- 首次使用单独同意（不默认勾选、不捆绑），同意页列明 8 项：收集项（含**性别（选填）**）、用途、保存期限、第三方受托处理方（火山引擎，北京火山引擎科技有限公司，境内）名称/所在地、处理目的、数据类别、删除方式、拒绝后果；展示 18+ 声明；说明「性别不填不影响生成与参考尺码」（BR-11，CP-06，AC-21/25/26）。**兜底**：若未来改用境外供应商，须恢复境外接收方披露 + 出境合规评估，并再次变更 BR-11（REQ v0.4 BR-11，Q-9 历史答复保留）。
- 供应商与成本（REQ v0.4 §6.4/§10.4）：P1 试穿 API = 火山引擎「图片换装 V2」（境内 cn-north-1，不构成数据出境）；单次成本上限 **≤2 元/次**（Q-21，用户 2026-11-10），超出需先报用户批准预算；demo 优先使用供应商免费/试用额度，上线前按真实报价复核。
- 人体照片属敏感个人信息：最小化收集、可删除、禁止明文写本地 Storage，日志/埋点不含照片内容、三围与性别（BR-9）。
- 结果图界面「AI 生成」显式标识（demo 只强制显式；隐式元数据列上线前，BR-10，AC-18）。
- 不做提审/类目/资质/真实用户发布（Q-17）；demo 不接微信内容安全，由供应商审核兜底（Q-16）；全站无导购/销售元素（AC-23）。

## B. 数据契约

### B.1 云函数与统一响应

- 客户端 → `wx.cloud.callFunction({name, data:{action, ...payload}})`；云函数按 `action` 分发。
- 统一响应包裹（成功/失败都返回同一结构）：

```
{ ok: boolean, data: object|null,
  error: { code: int, name: string, message: string, hint: string, httpStatus: int }|null,
  requestId: string, serverTime: int }
```

- `requestId` 服务端生成（uuid v4），贯穿日志；`serverTime` 为服务端 epoch ms，端上以服务端时间计算等待时长，避免手机时钟漂移。
- 云函数配置：超时 20s、内存 256MB；`precheck` 目标 p95 ≤5s（硬超时 8s）；`taskGet` 硬超时 8s。
- 错误 `code` 与 `httpStatus` 语义见「边界与错误处理」错误码表；云函数返回 HTTP 200 时由 `ok=false` + `error.httpStatus` 表达语义，便于 AC-20 断言。

### B.4 供应商契约抽象与契约桩

服务端内部接口（`VendorAdapter`，Node，运行于云函数；契约基线见 SPIKE-0001 §4/§6）：

```
validate({buffer, mime, kind}) -> {status:"pass"|"fail"|"unknown", checks?:[{code,status:"pass"|"fail"|"unknown",hint?}], failed?:string[], unknown?:string[], detail?}
submit({personBuffers[], garmentBuffer, metrics}) -> {vendorTaskId}
query({vendorTaskId}) -> {state:"PENDING"|"RUNNING"|"SUCCEEDED"|"FAILED", imageBuffer?, width?, height?, failureCode?}
cancel({vendorTaskId}) -> void|unsupported
erase({vendorTaskId}) -> void|unsupported   // 供应商无能力时返回 unsupported，仅删我方副本
health() -> {ok, latencyMs}
```

- **validate 三态基线**（SPIKE-0001 §6）：只有 `status="pass"` 可进入 `createTask`；`fail` 返回预检子码；**`unknown` 不得被当作 `pass` 放行** → `precheck` 返回 `pass:false` + `E_PRECHECK_UNKNOWN`（3013），提示「照片校验暂时无法完成，请换一张或稍后重试」，不创建任务、不扣额度。
- **供应商无独立预检端点**（SPIKE-0001 §6.1：Perfect Corp / 腾讯云 MPS 文档只有生成接口与事后失败码；火山引擎「图片换装 V2」官方文档正文不可抓取，**是否有 validate 端点待凭证实测确认**）：L1 服务端二次校验不依赖供应商 `validate`，由服务端 `PrecheckAdapter`（视觉模型或规则，**方案待选型**，超时 8s 硬截断）产出结构化 `checks`；供应商 `validate` 能力探测结果记 `unknown`。供应商生成失败码映射为 `E_PRECHECK_*`（422）并给可执行提示，作为兜底（风险登记见 R-5）。

### B.5 云存储路径与访问

- 路径：`sinn/person/{yyyyMMdd}/{uuid}.jpg`、`sinn/garment/{yyyyMMdd}/{uuid}.jpg`、`sinn/result/{yyyyMMdd}/{taskId}.png`；路径不含 `openid` 明文（记录在 DB 中做归属校验）。
- 上传：客户端 `wx.cloud.uploadFile` 直传；`assetRegister` 校验大小/尺寸/格式并绑定 `openid`。
- 读取：`taskGet` 仅向任务 owner 返回结果 `fileID`；`<image src="cloud://...">` 直接渲染。demo 云存储安全规则设为「已登录可读、客户端不可写删除」（实际删除全部走云函数）；**该规则无法按文件粒度隔离**，属已知风险（R-12），上线前改为自建对象存储签名 URL。
- 删除：删除接口在同一次云函数执行内 `cloud.deleteFile` 删除人像/衣服/结果对象并物理删除 DB 记录（失败即整体失败，保证「删除成功返回前已删净」）；`cleanup` 仅对**未删除且已到 `purgeAt`** 的任务批量兜底。

### B.6 时间、ID、数值精度

- ID：`taskId` = `t_` + 24 位 hex（string）；`assetId` = `a_` + 24 位 hex；`clientReqId` = UUID v4（string）；`vendorTaskId` = 供应商原样 string。
- 时间：统一 epoch ms 整数（number，安全整数范围内）；展示时由端上格式化；跨天重置用 Asia/Shanghai `dayKey` 字符串。
- 数值：`heightCm` 整数（100–250）；`weightKg` 1 位小数（25.0–250.0）；`chestCm`/`waistCm`/`hipCm` 1 位小数（40.0–200.0），选填。传输用 number；服务端落库转整数最小单位（cm → mm 整数；kg → g 整数）避免浮点误差；接口返回时还原。
- `gender`：string 枚举 `male` / `female` / `unspecified`；选填，缺省/未传按 `unspecified` 处理，可跳过不阻塞生成；非法值返回 `E_PARAM`；落库字段 `sinn_tasks.metrics.gender`；端上不缓存（见 §C）。
- 结果图尺寸：`width`/`height` 整数 px；长边 ≥2048 优先，降级分支 ≥1536 且需记录用户复核（Q-11，CP-07）。

## D. 分包与包体积预算

当前基线：**DEV-0001-10 实测主包 173.9KB**（2026-11-09；7 页、无分包、无第三方运行库/图片/字体/未登记资源；历史可追溯：SPIKE-0001 后 25.7KB → DEV 完成后 173.9KB）。内部预算调整为 **200KB**（= 实测 173.9KB × 1.15，约 15% 增长余量；仍远低于平台硬限 2048KB）。**无分包**（理由：P1 体积远低于平台上限，拆分包增加路由复杂度；触发条件：实测主包 >1200KB 时重评）。

## 边界与错误处理

| 场景 | 期望行为 |
|---|---|
| 未同意/拒绝隐私授权 | 不调用任何隐私 API；停留首页功能说明；提示「同意后才能使用拍照/选图」；不创建任务 |
| 18+ 未确认 | 无法进入上传页（AC-25）；consent 页按钮禁用 |
| 人像照片 0 张 / 衣服照片缺失 | 「开始生成」禁用；绕过 UI 调 `createTask` 返回 `E_PARAM` + 缺失项名称（AC-1） |
| 身高/体重缺省、越界、非数字 | 端上拦截并提示字段；服务端二次校验返回 `E_PARAM` |
| 性别未选 | 不拦截，按默认 `unspecified` 处理（AC-1/AC-26）；非法值（非 `male`/`female`/`unspecified`）服务端返回 `E_PARAM` |
| 三围留空/部分填写 | 不拦截；参考尺码按第 5 节降级规则展示 |
| 照片格式/大小/长边超限 | L0 ≤300ms 拦截，提示具体原因，不上传、不创建任务 |
| 人像非全身/遮挡/多人/逆光 | 服务端 `precheck` 返回 `pass:false` + 对应子码 + 重拍建议；`createTask` 调用 0 次（AC-2..5） |
| 衣服吊牌/多件/模特上身/电商图 | 同上，返回衣服类子码（AC-24） |
| 预检接口超时/供应商不可用 | 提示「照片校验暂时不可用，请稍后重试」；不创建任务；不扣额度 |
| 预检通过但生成时供应商判不合格 | 任务 `FAILED`，失败类「照片/衣服不合格」，返还额度；失败页不出图（AC-6/BR-7） |
| 预检返回 `unknown`（供应商无预检端点/视觉模型无法判定） | **不视为通过**：`precheck` 返回 `pass:false` + `E_PRECHECK_UNKNOWN`(3013)，提示「照片校验暂时无法完成，请换一张或稍后重试」；不创建任务、不扣额度（SPIKE-0001 §6） |
| 额度不足（普通第 2 次/VIP 第 11 次） | `E_QUOTA_EXHAUSTED` + `resetAt`；端上提示「今日额度已用完，明日 00:00 重置」；任务创建 0 次（AC-11） |
| 已有进行中任务 | `E_ACTIVE_TASK_EXISTS` + `existingTaskId`；端上恢复该任务，不重复扣额度（AC-12） |
| 重复点击/重复提交 | 幂等返回同一 `taskId`；额度只扣 1 次（AC-12） |
| 上传失败/断网 | 提示重试；不进入生成；不扣额度；重试不产生重复资产 |
| 生成超时（60s） | 服务端 `TIMEOUT` + 返还额度；端上 60–65s 内进入超时态 + 重试按钮；结局不出图（AC-9） |
| 供应商限流/5xx/排队超时 | 先显示排队态与已等待时长，最终 `E_VENDOR_UNAVAILABLE`；返还额度；文案可行动 |
| 内容安全拦截（供应商返回） | `E_CONTENT_BLOCKED`；失败类「内容安全拦截」；返还额度；不出图（AC-10） |
| 供应商返回不可解析 | `E_VENDOR_RESPONSE_INVALID`；任务失败 + 返还额度；记录 vendor 响应摘要（不含图片内容） |
| 生成中离开页面/杀进程 | 重进后 `profile.activeTaskId`/本地缓存恢复同一任务；不重复创建、不重复扣额度（AC-12） |
| 用户取消 | `cancelTask` → `CANCELLED` + 返还额度；端上回首页 |
| 任务不存在 | `E_TASK_NOT_FOUND`（404） |
| 任务已删除/已到期清理 | 统一 `E_TASK_NOT_FOUND`（404）；`E_TASK_GONE`（410）保留不用；不展示结果（AC-20） |
| 重复删除任务 | `deleteTask` 返回 404（按不存在处理）；`deleteAll` 幂等成功，返回本次 `deletedAt` |
| 越权访问他人 taskId | 统一按 404 处理，不泄露存在性；内部告警 |
| 删除确认取消 | 不删除，状态不变（AC-19） |
| 删除后再次查看 | 用户侧不可见；云存储对象不存在（HEAD 404）；DB 任务记录与资产记录不存在（`auditTask` 断言 `exists=false`）；查询 404（AC-20） |
| 撤回同意 | 删除全部数据 + 清本地缓存；回首页重新同意；同意审计保留（不含照片/围度） |
| 跨天 00:00 边界 | 服务端按 `dayKey` 惰性重置；端上以服务端返回为准；展示重置时间 |
| 云函数冷启动/超时 | 端上重试 1 次（指数退避）；仍失败给「服务暂时不可用」文案；不重复扣额度 |
| 日志/埋点 | 只允许 `requestId/taskId/action/code/latencyMs`；禁止照片内容、三围、openid 明文 |
| 本地 Storage 版本迁移 | 读旧键 → 校验 → 迁移；失败则清空并回退服务端状态 |

## 非功能要求

- 性能：点击「开始生成」到结果图 `onload` 完成 ≤60s（AC-7，3/3）；阶段预算：上传 ≤8s、预检 ≤5s、提交供应商 ≤10s、生成 ≤40s、转存与下载 ≤5s；`taskGet` p95 ≤2s；预检接口 p95 ≤5s（硬超时 8s）；冷启动后首个请求 ≤3s；端上页面切换 ≤300ms；图片缩放交互帧率 ≥45fps（S2+/S2 需 SPIKE-0001 真机实测；当前未实测，CP-12）。
- 兼容：skyline + glass-easel + 自定义导航栏；最低基础库 3.0.0；无分包、无 tabBar；iPad 内容最大宽度 750rpx 居中；安全区适配；深色模式不启用；真机机型矩阵人工核对（RK-8）。
- 权限：仅相册/摄像头/隐私授权三个授权点（F 节）；未同意不调用；`wx.*` 隐私 API 全部通过统一 `services/consent.js` 前置校验；无 `eval`/`new Function`/动态 require（REQ §6.5）。
- 安全：身份只用 `cloud.getWXContext().OPENID`；不接受客户端传入的 openid；所有任务/资产读写校验归属；供应商密钥仅云函数环境变量；日志脱敏；测试审计接口仅测试环境开放。
- 可观测性：结构化日志 `{requestId, action, taskId, code, latencyMs}`；错误码统一；`requestId` 返回端上便于对账。
- 可用性：demo 不承诺 SLA（Q-18）；供应商不可用时给明确排队/失败文案，不静默失败。
- 合规：BR-8/9/10/11 全部落到 F-1/F-9/F-11/F-12；demo 与上线版差异列表引用 REQ §3.3，不得把上线版要求写进 P1 验收。
