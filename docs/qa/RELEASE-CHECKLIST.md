# 小程序发布前检查单（人工卡点，agent 不得代签）

> 规则：本表任何一行未勾选，REPORT 结论只能是「有条件通过」。
> 每行填「勾选 + 执行人 + 日期」。发布/提审/回滚动作本身由人执行。

## 1. 技术就绪（提审前，DEV + QA）

- [ ] `tools/check-gates.ps1` PASS，`tools/check-wxapp.ps1` PASS
- [ ] `npm test` 全绿；L3 端到端全部通过或已明确标注阻塞原因
- [ ] 主包 / 各分包体积实测值已回填 SPEC 预算表，且未超限
- [ ] 基础库版本已在后台设置，低版本降级路径已实测
- [ ] 网络请求域名已配置且无「不校验合法域名」残留
- [ ] `project.private.config.json` 未入库；仓库无密钥、无测试账号密码
- [ ] `console.log` 与调试开关已清理；错误上报已接入（或明确不接）
- [ ] 真机（至少 iOS + Android 各一台）完整走通主链路
- [ ] 弱网/断网/超时三种异常下的页面表现已确认（不白屏、不卡死）

## 2. 合规与材料（提审前，产品负责人）

- [ ] 服务类目已选定，所需资质已上传（教育/医疗/金融/招聘等特殊类目）
- [ ] 用户隐私保护指引已填写，且与 SPEC 的「隐私与授权点」逐条对应
- [ ] 每个隐私 API 都有使用场景说明，无"申请了但没用"的权限
- [ ] 有用户生成内容时：内容安全接口已接入、举报入口存在
- [ ] 虚拟支付、诱导分享、诱导关注等红线已排查
- [ ] 版本说明、测试账号（如需登录）、审核截图已准备
- [ ] 客服/反馈入口存在且可用

## 3. 发布动作（由人执行）

- [ ] 上传体验版 → 用体验版完整回归一次（不要用开发版代替）
- [ ] 提交审核，记录提审时间与版本号
- [ ] 审核通过后按计划发布（全量 / 分阶段）
- [ ] 保留上一版体验版与代码 tag，明确回滚方式（小程序无服务端回滚，只能重新提审旧版本）

## 4. 发布后 24 小时

- [ ] 线上主链路抽检（真机）
- [ ] 错误上报与性能数据无异常峰值
- [ ] 用户反馈渠道无集中报错
- [ ] 如需紧急修复：走「加急审核」流程，且修复分支必须重跑第 1 节
