>
> 2026-11-12 用户已对 v0.1 §9 的十条待确认全部拍板（见 §10.5），其中 Q-1/Q-2/Q-3/Q-4/Q-5/Q-9 又以 v0.3 口径覆盖 v0.2（§10.5 表中已标「v0.3 覆盖」）。§9 已无待确认项；衍生问题只进 §6 RK。调研与候选池见 §12；外部资料会变化，候选池不构成技术选型结论；供应商由 SE spike 后决定，本 REQ 不承诺具体供应商与价格。

## 1. 背景

### 1.1 用户原始诉求

用户 2026-11-09 提出（`RQ-0001`，不可改）：上传自己的照片、身高体重和三围 → 生成贴近真实的虚拟形象 → 上传衣服照片 → 模拟穿在自己身上 → 看是否合身 → 放大看细节。该诉求在 P1 被拆为：身体数据采集、生成虚拟形象、虚拟试穿、放大细节（R1–R4）。

### 1.2 P1 现状（二期起点）

P1（2D 试穿 demo）已完成端到端真实链路，`REPORT-0001` v0.8 的结论是 **「不通过（demo 阶段阻塞）」**，阻塞项为外部项（真机、VIP 规则、素材、报价、正式隐私文本等），不是功能链路未跑通。本 REQ 只把 P1 当作既有起点，**不表述为「P1 已验收通过」**。

P1 已具备、P2 直接复用的基础：

- 微信云开发后端：云函数、云数据库、云存储；端上不持有供应商凭证。
- 采集与校验：1 张全身正面必填 + 可选 ≤2 张补充；身高体重必填；性别/三围选填；人像/衣服合格性预检；端上照片自动适配（长边 ≤4096px、≤5MB、JPG）。
- 异步任务 + 轮询：`wx.request` 有 60 秒硬超时，服务端建任务、端上轮询；2D 端到端 96 秒预算（P1 口径，仅约束 2D）。
- 参考尺码：GB/T 1335 双表（男装 1335.1 / 女装 1335.2），XS–XXL 六档；文案标注「参考、不承诺合身」。
- 隐私与删除：小程序内单独同意、第三方受托处理方披露、18+ 声明、AI 生成显式标识、删除即物理全删（对象 + 记录，无墓碑，≤24 小时留存）。
- 低版本兜底：`wx.getSkylineInfo` 缺失/不支持时提示升级，不白屏。

### 1.3 二期启动与用户拍板

用户 2026-11-12 决定启动二期（P2），并拍板三项（原话引用，见 §10.1）：

1. 二期核心形态 = **轻量 3D 形象（可旋转查看）**；
2. 3D 技术路线 = **采购 3D 生成 API（照片→3D 模型）**，端上只渲染与交互；
3. 二期范围 = **3D 形象旋转/多角度查看 + P1.1 单件下装/裙装/外套（2D）+ 历史形象库 + 保存到相册**，**不含**多件叠穿/上下装组合。

用户同日补充（原话，见 §10.2）：「预算充足，无需考虑这个，你只需要考虑可行性，达到最佳实现效果即可。」据此，成本不作为二期选型约束；成本只在 §12 附录记录计费方式与估算区间，不承诺单价。

同日用户对 v0.1 §9 的十条待确认逐条拍板（见 §10.5）；随后又对其中 Q-1/Q-2/Q-3/Q-4/Q-5/Q-9 给出 v0.3 覆盖口径（生成时长放宽到 5 分钟内、结构保真不重绘面部、历史库不设上限、只保存不站内分享、优先真机验证、复用 P1 同意流程）。本文以 v0.3 口径为准，§9 已无待确认项。

### 1.4 本 REQ 的边界

- 只定义 P2 + P1.1 的需求与验收口径；不写 SPEC、不写 TASKS、不写代码、不做技术选型。
- 3D 渲染（xr-frame / WebGL）在 skyline + glass-easel 下的可用性属于待验证前置（见 §6.6 RK-1），本 REQ 只写风险与验收要求。
- 3D 生成 API 的供应商与输出格式不在本 REQ 下结论；候选池与对比维度见 §12。
- 若候选 API 无法满足 §10.5 的「结构保真」口径，必须按 RK-14 回报用户，不得私自降级为「允许 AI 重绘」。

## 2. 目标

**一句话目标**：用户在 P1 既有采集流程中上传 1–3 张全身照，经服务端异步调用 3D 生成 API，得到可旋转、可多角度查看、带纹理、**结构保真**（不重绘五官与发型主体）的轻量 3D 形象；该形象在 demo 期不限数量与保留期地保存在历史形象库中，可切换、可删除（支持删除全部）；可保存当前视角 JPG 到相册（水印含「AI 生成」），**不做站内分享**；同时 P1.1 支持单件下装/裙装/外套的 2D 试穿，复用 P1 的校验、异步、尺码与删除链路。

**可验收的子目标**：

1. **3D 生成**：1 张必填 + 可选 ≤2 张照片可生成；端到端预算 **≤300s**（服务端任务默认 300s 超时，可 env 覆写；端上硬上限 310s）；生成中可离开页面、回来可恢复；进度按阶段展示并给「预计仍需 X 秒」类提示，不造假百分比；记录真实耗时（P50/P95 如实写，不得把 300s 写成常态）；成功、失败、超时三类均有明确状态与文案，失败不静默、不产出占位图。
2. **3D 查看**：水平 360° 旋转、俯仰 ±30°、双指缩放 0.8x–2x、自动旋转开关；旋转过程无空白帧、无模型消失；手势冲突有明确规则。
3. **历史形象库**：demo 期**不设数量与保留期上限**，生成多少保留多少，直到用户主动删除；提供「删除全部」；撤回同意同样物理删除全部 3D 资产；存储增长与清理策略缺口写 RK-15，上线前必须补容量/保留期策略。
4. **保存与传播**：只保存当前视角静帧 JPG 到相册，图片内烧入「AI 生成」标识（水印）；**不做站内分享**（无 `onShareAppMessage`/朋友圈）；不导出 glTF/GLB、不导出视频；不提供他人肖像传播路径。
5. **P1.1**：单件下装/裙装/外套的 2D 试穿成功，尺码口径与免责文案沿用 P1。
6. **隐私**：demo 复用 P1 同意流程，在同意页披露中新增「3D 人像建模」一节（用途/留存/可删可撤回）；不做 3D 单独同意页，但上线前必须补 3D 单独同意与隐私评估（见 §3.3 第 13 行、RK-16）。
7. **额度**：demo 阶段 3D 不限额（不扣次数、失败不涉及退额度），但单用户同时最多 1 个进行中的 3D 任务；保留可配置日上限（默认 0 = 不限）作为事故保护；P1 的 2D 额度不变。

## 5. 业务规则

| 编号 | 规则 |
|---|---|
| BR-1 | **3D 输入照片要求**：复用 P1 BR-1（1 张全身正面必填，可选 ≤2 张补充；身高体重必填；性别/三围选填）。3D 额外要求：单人、全身或至少膝上、正脸清晰可见、光线均匀、无遮挡、长边足够（具体像素下限由 spike 定，原则不低于 P1 的 2048px 优先口径）。**结构保真**：不允许 AI 重绘五官与发型主体；只允许最小必要补全（后脑勺、耳朵、被遮挡区域、边缘接缝），补全不得改变五官形状/比例/位置。不合格必须明确提示并拒绝生成，禁止静默生成一张错模型。 |
| BR-2 | **供应商输入规格**：每张照片长边 ≤4096px、≤5MB、JPG；复用 P1 BR-12/BR-14 的端上自适应（4096→3072→2048，最小 1024，先降质量再降尺寸）；因供应商限制压缩时提示「已自动优化照片（供应商限制）」；压缩失败返回 5007，不建任务、不扣额度（demo 3D 本就不扣次数）。 |
| BR-3 | **3D 生成状态与时限**：状态 排队 → 建模 → 贴图/保存 → 成功 / 失败 / 超时。**端到端预算 ≤300s**（用户拍板 5 分钟内均可接受）：服务端任务超时默认 **300s**（保留环境变量覆写），端上硬上限 **310s**；计时边界 = 服务端 `createTask` 成功返回 → 模型文件可访问且可被加载器解析。生成中允许离开页面，返回后按 taskId 恢复；进度按阶段展示并给「预计仍需 X 秒」类提示，**不得造假百分比**；超过 310s 才判超时并给失败文案。**记录真实耗时**：服务端记录每次生成耗时并输出 P50/P95；文案/文档不得把 300s 写成常态（300s 是上限，非常态时长）。 |
| BR-4 | **失败分类**：照片不合格 / 内容安全拦截 / 网络失败 / 供应商不可用 / 生成失败 / 超时 / 模型文件损坏。每类有明确文案与下一步（重拍、重试、删除），禁止占位图、禁止静默失败；失败与超时后的留存按 BR-15。 |
| BR-5 | **旋转交互**：单指水平拖拽 360° 连续旋转；上下俯仰 ±30°（超出回弹）；双指缩放 0.8x–2x；提供自动旋转开关（默认关闭）。手势冲突规则：双指缩放时暂停自动旋转与单指旋转，缩放结束后恢复；单指拖动只旋转不缩放；缩放/俯仰到边界时回弹。旋转不改变模型数据、不进入编辑态；不得出现空白帧或模型消失。 |
| BR-6 | **历史形象库**：**demo 期不设数量与保留期上限**，生成多少保留多少，直到用户主动删除；生成成功自动入库；列表按时间倒序，显示缩略图、生成时间、状态；支持单条删除与「删除全部」；「删除全部」与撤回同意必须物理删除全部 3D 资产（历史库 + 云存储对象 + 记录 + 本地缓存）；以账号同步，不依赖本机缓存；**存储会按量增长，上线前必须补容量/保留期/清理策略**（见 RK-15）。 |
| BR-7 | **保存到相册**：保存当前 3D 视角的**静帧 JPG**，图片内**烧入「AI 生成」水印**（非仅界面提示）；需相册权限，拒绝时提示但仍可在历史库查看；**不导出 glTF/GLB、不导出旋转视频**；3D 形象只在小程序内查看。 |
| BR-8 | **保存与传播边界**：**只保存到相册，不做站内分享**——不提供 `onShareAppMessage`/`onShareTimeline`/朋友圈入口；无他人肖像传播路径；不提供「帮别人生成」；保存图必须带水印。 |
| BR-9 | **AI 标识**：3D 查看页固定位置显示「AI 生成」；保存图片内烧入显式水印；上线前补隐式元数据（生成合成属性、服务提供者名称或编码、内容编号）；用户协议说明标识方式与样式。 |
| BR-10 | **额度与并发（demo）**：3D **不限额、不扣次数**，失败/超时也**不涉及退额度**；但**单用户同时最多 1 个进行中的 3D 任务**，重复提交返回「已有任务进行中」；系统保留可配置的日生成上限（默认 0 = 不限，仅用于事故保护，配置后超限拒绝并提示）；P1 的 2D 额度规则不变。 |
| BR-11 | **删除语义**：删除单条 3D 形象 = 物理全删该形象对应的云存储对象 + 数据库记录 + 本地缓存，无墓碑、无 PURGED 状态；**「删除全部」/撤回同意 = 物理全删该用户全部 3D 资产（含历史库、云存储对象、数据库记录、本地缓存）**；删除响应返回 `deletedAt` 但不落库；删除后资产查询返回 404/410；24 小时定时清理只处理未删除任务；同意审计（openidHash/版本/时间/撤回）按 P1 口径保留。 |
| BR-12 | **隐私与同意**：demo **复用 P1 同意流程**，在同意页披露中新增一节「3D 人像建模」：人像建模、收集与使用目的、第三方受托处理方名称/所在地/数据类别、留存说明、可删除、可撤回、拒绝后果、18+；**不做 3D 单独同意页**；撤回同意 = 物理全删 3D 资产与记录；若候选为境外服务，同意页必须披露境外接收方并完成出境评估（上线前）。**上线前必须补 3D 单独同意与隐私评估**（见 §3.3 第 13 行、RK-16）。 |
| BR-13 | **低版本兜底**：复用 P1 BR-13。3D 入口在 `wx.getSkylineInfo` 缺失、基础库过低、或 xr-frame/WebGL 不可用时，提示「当前微信版本/设备不支持 3D 查看，请升级微信或使用 2D 试穿」；不白屏、不崩溃、不静默失败；2D 功能不受影响。 |
| BR-14 | **demo 合规边界**：内部 demo 不选类目、不办资质、不接入微信内容安全（由 3D 供应商审核 + 人工抽检兜底）；上线前必须接入微信内容安全并完成 `REPORT` 中的卡点；demo 不承诺 SLA、不对外宣传；**真实 3D API 按量计费，demo 不限额的成本敞口按 RK-13 管理，上线前必须改为限额/计费**。 |
| BR-15 | **失败/超时留存**：3D 生成失败或超时后，原始照片与 3D 中间产物**保留 24 小时可重试**；24 小时后由清理任务物理删除（对象 404、记录不存在）；用户主动删除或撤回同意时立即物理全删，不等 24 小时；失败留存不得用于其他目的。 |

## 6. 约束

### 6.1 技术基线

- 渲染器 skyline + glass-easel + 自定义导航栏（沿用 P1，经用户拍板不改 webview）。
- **端上只做渲染与交互，不做任何推理**：3D 生成、照片解析、模型后处理全部在服务端/供应商侧。
- 3D 渲染方案（xr-frame 扩展库 / WebGL / 其他）必须先在 skyline + glass-easel 下做 spike；本 REQ 不指定实现。
- 手势与渲染：skyline 下 `movable-view` 不被支持；旋转/俯仰/缩放手势需自实现或使用受支持的方案（P1 的 2D 双指缩放已用 worklet/S2 方案，3D 需单独验证）。
- **与 P1 口径核对**：P1 AC-7 的 96 秒只约束 2D 试穿，3D 按 Q-1 的 ≤300s，两者不冲突；供应商输入 ≤4096px/≤5MB、低版本兜底 8.0.30/3.0.0 沿用 P1；无其他冲突。
- 新增渲染库/加载器/着色器资源必须登记进 SPEC 的包体积预算表。

### 6.2 网络与异步

- `wx.request` 有 60 秒硬超时，3D 生成可达分钟级 → **必须服务端异步任务 + 端上轮询**，不得端上直连供应商、不得让单个请求挂满。
- 服务端 3D 任务超时默认 **300s**，保留环境变量覆写；端上硬上限 **310s**；轮询间隔与总时长按该预算配置。
- 生成中允许离开页面，返回后按 `taskId` 恢复状态；重复点击不重复建任务；同一 taskId 不重复提交/扣费（demo 不扣次数，但仍要防重复创建）。
- 供应商凭证只放云函数环境变量，端上不可见。
- 保存相册涉及的 downloadFile/临时文件域名必须提前在公众平台配置。

### 6.3 包体积与资源

- 主包 ≤2MB、单分包 ≤2MB、全部分包合计 ≤20MB，超限即 FAIL（`tools/check-wxapp.ps1`）。
- 3D 模型与纹理不进小程序包，走云端下载 + 本地缓存；缓存必须有上限与清理策略。
- 新增依赖/资源/渲染库前先在 SPEC 预算表登记预计增量；主包当前实测约 200KB，3D 新增资源不得让主包逼近硬限。
- glTF/GLB + 纹理的加载内存与首屏时间必须可测；低端机不得因加载导致白屏（降级见 BR-13）。

### 6.4 隐私与合规

- 人体照片、3D 形象、历史形象库均属敏感个人信息：单独同意、最小化收集、可删除，三者缺一不可。
- **demo 复用 P1 同意流程 + 「3D 人像建模」披露节**（用途、留存、可删可撤回、第三方受托处理方）；不做 3D 单独同意页，但上线前必须补 3D 单独同意与隐私评估（RK-16），该缺口不得被当作已满足合规。
- 若 3D 供应商为境外主体（如 Ready Player Me 类），demo 阶段以「披露 + 单独同意」为基线，上线前完成出境评估；不得默认静默出境。
- AI 生成内容标识：查看界面、保存图片水印显式标识；上线前补隐式元数据；用户协议说明标识方式。
- 保存到相册需相册权限；不做站内分享，因此无朋友圈传播路径；仍禁止他人肖像传播。
- 18+ 声明 + 条款禁止未成年人使用；不做实名硬核验。
- 内部 demo 不选类目、不办资质、不接入微信内容安全；上线前必须补齐（见 §3.3）。

### 6.5 安全

- 禁止 `eval`、`new Function`、动态拼接 `require`/`import()`（`check-wxapp.ps1` FAIL）。
- 3D 模型文件必须校验来源、格式、大小，防止恶意文件；下载 URL 使用短期签名，不暴露长期地址。
- 云存储按用户隔离访问（P1 遗留的 R-12 存储隔离问题在 P2 复用前必须确认修复方案）。
- 保存/缓存内容不得包含原 3D 资产 URL、用户 openid 或可反查信息。

## 7. 验收口径（AC-1–AC-30）

**判定原则**：

- 每条 AC 必须能被**单个测试用例**验证；涉及视觉的用固定样张 + 明确的通过/不通过标准，不使用主观感受类表述。
- 标注（自动化）的用 `miniprogram-simulate` + jest + `tests/mocks/wx.js`；标注（人工）的必须写进 `RELEASE-CHECKLIST` 并注明环境依赖（真机/开发者工具缺失时标「阻塞」，不得标「通过」）。
- 标注（门禁）的由 `tools/check-wxapp.ps1` 或静态检查证明。

| 编号 | 验收标准 |
|---|---|
| AC-1（自动化） | 上传 1 张必填全身照 + 2 张补充照，mock 供应商返回有效 glTF/GLB；`createTask` 成功、轮询到成功、模型 URL 可访问且加载器解析成功；端到端 **≤300s**（服务端任务超时默认 300s 可 env 覆写、端上硬上限 310s）；生成中离开页面再返回可恢复；进度按阶段展示并带预计剩余时间提示，不出现造假百分比；服务端记录真实耗时并可输出 P50/P95。 |
| AC-2（自动化） | 0 张照片 → 拦截并提示；1 张必填 → 可提交；3 张（1+2）→ 可提交；4 张 → 拒绝并提示上限。 |
| AC-3（自动化） | 非全身、多人、遮挡、逆光、分辨率过低各 1 例固定样张 → 预检拒绝，`createTask` 调用 0 次，提示对应文案；不得生成任何结果。 |
| AC-4（自动化） | 6MB/4000px 样张 → 自动压到 ≤5MB 且长边 ≤4096，提示「已自动优化照片」；质量最低仍超 → 逐档降尺寸；<1024 → 拒绝；压缩失败 → 5007、`createTask` 0 次。 |
| AC-5（自动化） | 成功结果包含 glTF/GLB + 纹理文件；加载器解析成功；节点/骨骼数量 >0，可绕 Y 轴旋转；损坏文件 → 失败文案 + 可重试，不白屏。 |
| AC-6（人工） | 真机（至少 iOS + Android 各 1 台）：单指水平拖拽 360° 连续旋转，每 45° 截图 1 张共 8 张，均可渲染、无空白帧、无模型消失；俯仰在 ±30° 内、超出回弹；双指缩放 0.8x–2x 生效；自动旋转开关可开/关；双指缩放时暂停旋转、结束恢复；连续操作 60 秒不崩溃。 |
| AC-7（自动化） | 生成成功后自动进入历史库；列表显示缩略图、生成时间、状态；按时间倒序；切换后加载对应模型成功。 |

### 12.2 对比维度（spike 时逐项打分）

1. 输入要求：支持张数、是否必须全身、是否单人、对光照/背景/遮挡的容忍度、长边下限。

4. 耗时：单次生成时长、排队时间、失败率、稳定性；是否满足 ≤300s 预算。
5. 计费方式与试用：按次/按量/订阅、免费额度、是否需要商务开通（只记录，不作选型约束）。
6. 境内可访问性与资质：是否需要跨境、供应商资质、合同主体。
7. 数据留存与出境：留存时长、是否用于训练、删除接口、出境评估要求。
8. 商用授权：模型/纹理/输出的商用与二次分发权。
9. 技术集成：SDK/API 形态、回调/轮询、鉴权、文件大小限制。
10. **结构保真**：按 AC-25 检查不重绘五官/发型主体，只允许最小必要补全；量化指标（关键点位移、肤色 ΔE、发型轮廓 IoU）需可测。
11. 风险：接口下线、版本变更、配额与并发限制。

### 12.3 调研结论（只到「候选池」层）

- 共 6 家候选：腾讯云混元生3D、火山方舟 3D 生成、阿里云数字人、百度曦灵、Ready Player Me、魔珐星云。
